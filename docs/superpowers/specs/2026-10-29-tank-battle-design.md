# 坦克大战（网页版）设计文档

日期：2026-10-29
仓库：`Markwcl2004/tank-battle`
网址：`https://markwcl2004.github.io/tank-battle`

## 1. 做什么，为什么做

做一个照着 FC《坦克大战》（Battle City）复刻的网页游戏，给用户和大约十个朋友玩。点开链接就能玩，不用安装。每个人有自己的账号，存档跟着账号走，换设备也能接着玩。另外有一个排行榜，大家比分数。

朋友都在中国大陆，**不会翻墙**，这条约束决定了下面大部分技术选择。

## 2. 目标

- 单人闯关，玩法、地形、敌坦、道具都照 FC 原版做。
- 电脑和手机都能玩。手机用户可能是在微信里点开的链接。
- 用昵称加密码登录，不用邮箱。存档存在云端，换设备登录后接着玩。
- 排行榜显示每个人的单局最高分。
- 十来个人同时在线也没问题。游戏逻辑全在浏览器里跑，服务器只处理登录、存档和排行榜，并发压力可以忽略。

## 3. 不做的

- 双人模式，不管是同屏还是联网。
- 联机对战、实时同步。
- 防作弊。都是熟人，分数靠自觉。
- 关卡编辑器、自定义关卡。
- 原版的音乐和贴图素材（见第 7 节）。
- 国际化。界面只做中文。

## 4. 反目标（做到这些就算失败，哪怕功能都能跑）

- 朋友不翻墙打不开，或者打开要等很久。
- 登录门槛高：要邮箱、要验证码、要下 App。
- 手机上玩不了，或者手感很差：摇杆不跟手、误触缩放或滚动页面。
- 存档丢失，或者两台设备的存档互相覆盖。
- 打开后有一段时间黑屏或卡在加载，看不出发生了什么。

## 5. 约束

- **托管：** 游戏放 GitHub Pages，纯静态文件。
- **后端：** Supabase 免费版，用它的 Auth 管账号，用 Postgres 存存档和分数。
- **国内可达性：** 页面不能依赖任何在大陆被墙或不稳的外部资源。不用 Google Fonts，**不用 cdn.jsdelivr.net**（大陆访问不稳）。用到的第三方库都下载到仓库里，和页面一起托管。
  - 2026-10-29 从一台不翻墙的大陆网络实测：`pages.github.com`、`supabase.com` 能访问，延迟 0.3–0.8 秒。项目自己的域名 `<ref>.supabase.co` 还没测，建好 Supabase 项目后要先从大陆网络测一次。
- **Supabase 免费项目连续 7 天没人访问会被暂停。** 恢复要去 Supabase 后台手动点。这一条要写进 README。
- **Supabase 账号得用户本人注册。** 用户需要创建项目，再把项目 URL 和 anon key 交给开发者。数据库建表的 SQL 由开发者写好，用户在 SQL Editor 里粘贴执行，或者给开发者一个 access token 让开发者直接执行。
- **微信内置浏览器可能拦截 github.io。** 上线后要实测。如果被拦，在 README 和游戏首页提示朋友"点右上角，选在浏览器打开"。

## 6. 已经定下的方案

### 6.1 玩法（照 FC 原版）

- 场地 13×13 大格，每大格再分 2×2 小格。砖墙按小格破坏，被打掉的是被击中的那一侧。
- 底部中间是老鹰基地，被打中就游戏结束。
- 地形：砖墙、钢墙、水、树林、冰面。
  - 钢墙只有火力满级（三颗星）的子弹能打穿。
  - 水挡坦克，不挡子弹。
  - 树林遮挡坦克，画在坦克上面。
  - 冰面上坦克会打滑。
- 每关 20 辆敌坦，从顶部三个出生点轮流出现，场上同时最多 4 辆。
- 敌坦四种：普通、快速、火力、装甲。装甲要打 4 下，被打时颜色会变。每关四种各出几辆照原版。
- 第 4、11、18 辆敌坦闪红光，打掉后在随机位置掉一个道具。
- 六种道具：头盔（临时无敌护盾）、时钟（敌坦全部定住一段时间）、铁锹（基地围墙临时变钢墙）、星星（玩家火力升一级，最多三级）、炸弹（场上敌坦全部消灭）、坦克（加一条命）。
- 玩家火力等级：0 级基础；1 级子弹变快；2 级可以同时有两颗子弹在场；3 级能打穿钢墙。被击中后降回 0 级。
- 玩家出生时自带几秒无敌护盾。
- 开局 3 条命。计分照原版：普通 100、快速 200、火力 300、装甲 400，吃道具 500，炸弹清掉的敌坦不计分。奖命照原版，20000 分奖一条命。这些数值是开发者凭原版资料定的，有出入以资料为准。
- 关卡：照原版复刻 35 关的布局和敌坦配置。第 35 关打通后回到第 1 关继续，敌坦变强，具体怎么变强由开发者定，要求难度逐轮上升、有上限，不能变成必死。循环后的分数照常累计并计入排行榜，排行榜上的"最远关数"按累计关数算，比如第二轮第 1 关记作第 36 关。
- 关卡数据（开发者的决定）：35 关都要做，但不阻塞上线。如果转录核对拖慢进度，可以先带已核对好的关卡上线，再陆续补齐，补齐前在第 N+1 关处循环回第 1 关。
- 每关结束显示结算画面：各类敌坦击毁数和得分。

### 6.2 美术和声音

- 贴图全部用代码自己画成像素风，造型和配色尽量接近原版的感觉，但不能直接用原版素材。
- 内部分辨率照 NES 的比例，按整数倍放大显示，像素保持清晰锐利（nearest-neighbor 缩放）。
- 音效用 WebAudio 合成：开火、击中砖墙、击中钢墙、敌坦爆炸、玩家爆炸、吃道具、过关。不用原版音乐。
- 浏览器要求先有用户操作才能出声，所以第一次点"开始游戏"时初始化音频。设置里可以关声音。

### 6.3 操作

- **电脑：** 方向键或 WASD 移动，空格或 J 开火，P 或 Esc 暂停。
- **手机：** 横屏玩。左下角是四方向虚拟摇杆，右下角是开火键。开火键按住就连发，受场上子弹上限限制。竖屏时整屏提示"请把手机横过来"。
- 手机上要禁止双击缩放、长按选中文字、页面滚动和下拉刷新。
- 只有四个方向，和原版一样。斜向输入取占比较大的那个方向。
- 手机布局（开发者的决定）：横屏时游戏画面居中，按整数倍或接近整数倍放大，左右两侧的空白放摇杆和开火键，尽量不压在游戏画面上。屏幕太窄放不下时，按钮半透明叠在画面边缘。

### 6.4 账号

- 用昵称加密码注册和登录，不用邮箱。
- 实现方式：Supabase Auth 的邮箱密码登录，把昵称拼成假邮箱，比如 `<昵称 UTF-8 的十六进制>@players.tank-battle.local`。英文字母不区分大小写（先转小写再编码）。在 Supabase 设置里关掉邮箱验证。昵称本身另外存一张表，在这张表上保证唯一。
- 昵称允许中文。长度和可用字符由开发者定。
- 忘记密码：由用户（管理员）在 Supabase 后台重置。游戏里只放一行提示"忘记密码请找 XXX"。
- 不登录也能玩（游客模式），但不存档、不上排行榜。游客模式下要有明显提示。
- 登录状态保存在浏览器里，下次打开不用重新登录。

### 6.5 存档

- 每关开始时自动存档，内容是：关卡号、剩余命数、火力等级、当前总分。
- 中途退出或关掉网页，下次从这一关的开头继续，数值用这一关开始时存的那份。
- 游戏结束（基地被打或命用完）后上传本局分数，然后存档清空，下次从第 1 关开始。
- 首页显示"继续游戏（第 N 关）"和"新游戏"。点新游戏时要先确认，因为会覆盖存档。
- 每个账号只有一份存档，整行一次写入，不能出现写了一半的损坏状态。
- 防止两台设备互相覆盖（开发者的决定）：存档带一个版本号，每次写入时检查云端版本号是否等于本机读到的那个，相等才写入并加一。不相等说明别的设备已经推进过，这时不覆盖，而是提示"存档已在另一台设备上更新"，让玩家选择载入新存档或放弃本机进度。新游戏要覆盖存档时也走同样的检查。
- 网络失败时不能卡住游戏：存档失败就在角落里提示一下，下一关再试；分数上传失败就先存在本地，下次打开再补传。

### 6.6 排行榜

- 每人只上一条，取历史单局最高分。显示名次、昵称、分数、那一局打到的最远关数、日期。
- 显示前 50 名。当前用户如果不在前 50，在底部单独显示自己的名次。
- 不登录也能看排行榜。

### 6.7 数据和安全

- 三张表：昵称资料（user_id、昵称）、存档（每人一行）、分数记录（每局一行）。
- 打开 Row Level Security：每个人只能读写自己的资料和存档，只能插入自己的分数；所有人都能读排行榜。
- 前端直接带 Supabase 的 anon key，这是 Supabase 的标准用法，安全靠 RLS 保证。不能在前端放 service_role key。

### 6.8 技术选型

- 纯 HTML、CSS、JavaScript 加 Canvas 2D，不用游戏引擎，也不用构建工具。仓库里的文件就是线上跑的文件。
- supabase-js 下载一份放进仓库，不走 CDN。
- 开发顺序（开发者的决定）：先做游戏本体，存档和排行榜放在一层独立的接口后面，先用浏览器本地存储实现，Supabase 就绪后再换成云端实现。万一 `<ref>.supabase.co` 在大陆不通，只需要换掉这一层，游戏本体不动。
  - 2026-10-29 用一个虚构的项目域名测试，域名解析不到，所以这项测试没有结论。要等真实项目建好再测。
- 目标是中档手机上稳定 60 帧。游戏逻辑用固定步长更新，和画面刷新分开，保证不同刷新率的屏幕上速度一致。

## 7. 版权

原版的贴图、音乐、关卡布局归南梦宫（现万代南梦宫）所有。这里的处理是：贴图和声音全部自己做；关卡布局按原版复刻。私下给十来个朋友玩，实际风险很低，但 github.io 上的仓库和页面是公开的。用户已经知道这一点。

## 8. 交给开发者自己决定的

- 代码结构和文件划分。
- 敌坦 AI 的具体逻辑：照原版"大致随机移动，有一定概率朝基地方向走"的感觉做，不要求逐帧一致。
- 各种速度、时长、闪烁节奏的具体数值：尽量接近原版。
- 35 关布局和每关敌坦配置的数据来源：从公开的资料转录。不要直接拷贝许可证不明的开源代码。
- 像素贴图的具体画法。
- 测试方式。至少碰撞、子弹打砖墙、存档读写这几块要有自动化测试。
- 首页、暂停、结算、排行榜等界面的样式：要有像素游戏的感觉，和游戏画面风格统一。

## 9. 上线检查

- GitHub Pages 能打开，从不翻墙的大陆网络测一次。
- `<ref>.supabase.co` 从大陆网络能访问，注册、登录、存档、排行榜都走通一遍。
- 微信内置浏览器打开测一次，结果写进 README。
- 电脑 Chrome、iPhone Safari、安卓 Chrome 各完整玩一关。
- README 写清楚：网址；Supabase 7 天不访问会暂停以及怎么恢复；怎么在后台重置密码。
